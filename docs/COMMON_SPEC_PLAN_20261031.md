# 共通仕様の独立改修計画（2026-10-31）

依頼の全仕様を対象とするが、各項目の完了は対応表で個別に判断する。既存のゲーム条件・保存キー・参加者・スコアは維持する。

1. 現在の有効登録、公開URL、Pages設定、既存検査とPRを確認する。
2. PRでは検査のみ、公開ブランチのマージコミットでは同じ成果物を検査後に公開する。公開ファイルを限定し古い実行を抑止する。
3. 発見した音設定・共有等の独立した不具合を回帰検査付きで修正する。
4. 既存検査と追加検査を実行。実機・本番公開・翻訳・名前識別移行など未完了を明記する。
5. 作業ブランチとDraft PRへ提出。マージと公開設定変更は行わない。

重要な制約：既存DBは表示名を参加者キーとする。表示名変更で別参加者にならない要件は画面だけでは満たせず、本人確認と既存記録の引き継ぎ方針を別途確定する。既存記録は変更しない。

## P0 公開順の補修（2026-11-02 JST）
- マージ前に管理者がPages Source=GitHub Actionsを読み戻す。現在値未確認・権限不足・legacyならマージ保留。設定変更はこのPRの自動操作に含めない。
- 完全な既存CIを再利用し、同じcommitが成功した場合だけ包装→配備。PRは検査のみ、main以外の手動実行/失敗/skip/cancel/古いSHAは公開しない。
- 本番Source/配備は未確認。15言語・任意名・音量UI等の共通仕様残件は対応表のまま保持し、P0修正を全要件完了と扱わない。
